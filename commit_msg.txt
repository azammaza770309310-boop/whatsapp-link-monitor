FEAT(CROSS-ACCOUNT-CAPTURE + STYLE-MATCH): request alerts styled like link channel + capture from ALL accounts (monitor + joiner) + race-safe cross-account dedup

Operator asked for three things:
1. Make the request alert message box look like the link channel's blockquote
2. Capture requests from ALL groups across monitor AND joiner (federal) accounts
3. Adding a new monitor/joiner account should auto-include its groups without duplicates

Changes (4 targeted edits to bot.py):

1. bot.py:Monitor.__init__ (L3035-3042): add self._request_sent dict +
   self._request_sent_lock = asyncio.Lock(). The lock is necessary because
   the dedup was previously check-then-set (no lock) -- two concurrent
   arrivals of the same (chat_id, msg_id) from monitor + joiner would
   both see the key absent and both send. Now the lock serializes:
   first account wins + records the key, second sees the key + skips.

2. bot.py:_handle_request_path dedup block (L5868-5894): wrap the
   check-then-set inside `async with self._request_sent_lock:`. Adds a
   logging.debug on dedup hit so the operator can see when cross-account
   dedup prevents a duplicate.

3. bot.py:_handle_request_path alert format (L5941-5978): restyled to
   match MessageFormatter.format_link_message:
     - <blockquote> wrapper (same as link channel)
     - "طلب مساعدة" header (matches link's "🔗 رابط محفوظ")
     - Field order: 👥 المجموعة, 👤 المرسل, 📟 الحساب, 🕒 التاريخ (NEW),
       📡 المصدر <code>, 🔑 الكلمات
     - "🔗 عرض الرسالة الأصلية" link text (matches link channel exactly)
     - "💬 نص الطلب" at bottom (matches link channel's "💬 النص")
     - HTML-escaped (XSS safety preserved)
     - Date field pulled from event.message.date in YYYY-MM-DD HH:MM format
       (same format as link channel's date_str)

4. bot.py:_run_user_client (L8710-8730): removed `if role == 'monitor':`
   gate around _register_user_handlers. Now BOTH monitor AND joiner
   accounts register NewMessage handlers -- request alerts capture from
   all groups across all accounts. Existing link dedup via MessageClaim
   (SQLite atomic INSERT OR IGNORE) prevents duplicate link processing
   across accounts; the new _request_sent_lock prevents duplicate request
   alerts.

How "new account -> new groups without duplicate" works:
- /login flow (L7270-7273) adds the phone to _user_tasks immediately +
  starts _run_user_client.
- _run_user_client connect -> authorize -> register handlers (now for
  ALL roles, not just monitor).
- NewMessage fires for every message in every group the new account is
  in (including new groups only the new account has).
- Same message in the same group: same key (chat_id, msg_id) ->
  _request_sent_lock race-safe prevents duplicate alert.
- Links: MessageClaim SQLite atomic INSERT OR IGNORE prevents duplicate
  link processing.
